# SUSU HelpDesk — React frontend

Адаптивный пользовательский интерфейс на React + TypeScript + Vite для текущего REST API проекта.

## Возможности

- Вход по email и паролю через `POST /api/v1/auth/login`.
- JWT Bearer для защищённых запросов.
- Обзор собственных заявок и счётчики статусов.
- Список заявок с поиском, фильтром статуса и постраничной загрузкой.
- Просмотр карточки обращения и срока выполнения.
- Создание обращения с выбором категории.
- Редактирование заголовка и описания только новой заявки.
- Адаптивная боковая навигация для мобильных экранов, состояния загрузки, ошибок и пустого списка.

Функциональность соответствует текущему контракту `docs/API.md`. База знаний, комментарии, вложения и функции оператора не реализованы в API, поэтому интерфейс не имитирует эти операции.

## Запуск

Требуется Node.js 20+ и работающий backend (по умолчанию `http://localhost:8000`).

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

Vite покажет адрес фронтенда (обычно `http://localhost:5173`).

Если API работает по другому адресу, задайте в `.env`:

```env
VITE_API_URL=http://localhost:8000/api/v1
```

После изменения `.env` перезапустите Vite. API должен разрешать CORS для адреса фронтенда (например, `http://localhost:5173`); при необходимости настройте middleware CORS в FastAPI. Не помещайте секреты backend в переменные `VITE_*`.

## Контракт API

- `POST /auth/login` — JSON `{ "email": "...", "password": "..." }`.
- `GET /categories` — категории для формы создания.
- `GET /requests?limit=100&offset=0` — страница заявок.
- `GET /requests/{id}` — детали заявки.
- `POST /requests` — `title`, `description`, `category_id`.
- `PATCH /requests/{id}` — только `title` и/или `description`.

Токен сохраняется в localStorage для сохранения входа после обновления страницы. JWT действует 30 минут; при 401 интерфейс возвращает пользователя на экран входа. Для production рекомендуется оценить модель хранения токена и использовать HTTPS.
